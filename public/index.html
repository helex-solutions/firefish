Firefish 🐟🔥

REST API for converting between FHIR Shorthand (FSH) and FHIR resources.

What it is

Firefish is a lightweight Express service that wraps the SUSHI and GoFSH compilers and exposes them over HTTP. It compiles FSH source into FHIR JSON resources and vice-versa, so authoring tools can offer FSH editing without bundling Node toolchains in the browser.

The source content is sent as the raw request body (no JSON envelope), the FHIR release is chosen by the path (/r4/…, /r4b/… or /r5/…), and any remaining compiler options ride on the Content-Type header — convenient for piping a .fsh or .json file straight from curl.

SUSHI — FSH to FHIR

POST /{r4|r5}/sushi accepts the FSH document as the request body. The FHIR version is set by the path; the remaining options ride on the Content-Type header (application/fsh; key=value; ...).

Supported options

  • canonical — canonical URL base
  • version — package version
  • logLevel — silly | debug | verbose | http | info | warn | error | silent
  • snapshot — boolean, include snapshot in output

Example

curl -X POST http://localhost:3000/r5/sushi \
  -H 'Content-Type: application/fsh; version=0.0.1' \
  --data-binary $'Profile: MyPatient\nParent: Patient\n* name 1..1'

GoFSH — FHIR to FSH

POST /{r4|r5}/gofsh accepts a FHIR resource (or array of resources) as the request body, with options on the Content-Type header (application/fhir+json; key=value; ...). The response is plain application/fsh.

Supported options

  • logLevel — silly | debug | verbose | http | info | warn | error | silent
  • indent — boolean, indent rules
  • style — map | string

Example

curl -X POST http://localhost:3000/r5/gofsh \
  -H 'Content-Type: application/fhir+json; style=map; indent=true' \
  --data-binary @StructureDefinition-MyPatient.json

Health check

GET /health returns a JSON document with the service status and version, suitable for Kubernetes/Docker health probes. 

$ curl http://localhost:3000/health
{"status":"UP","service":"firefish","version":"0.1.0"}
